# 界面外观：Codex 风格深色主题（设计）

## 目标

界面此前用的是 Qt 原生控件外观（浅色、带立体感），与这个工具的气质不符，也不利于长时间
看报告与脚本。目标：**照 Codex 桌面版的外观做一套深色主题**，让它看起来像同一类工具。

## 令牌来源（不凭印象调色）

从本机 Codex 桌面版的样式表里直接解出来的，路径：
`/opt/codex-desktop/resources/app.asar` → `webview/assets/app-*.css` → `electron-dark` 作用域。

| 用途 | Codex 原值 | 本项目令牌 |
| --- | --- | --- |
| 主背景 | `--gray-900` `#181818` | `bg` |
| 面板 / 编辑器 | `--gray-800` `#212121` | `bg_elevated` |
| 更深一层（只读底、凹陷） | `--gray-1000` `#0d0d0d` | `bg_under` |
| 文字 主 / 次 / 三级 | `#fff` / 70% 白 / 50% 白 | `fg` / `fg_secondary` / `fg_tertiary` |
| 边框 浅 / 常规 / 重 | 4% / 8% / 16% 白 | `border_light` / `border` / `border_heavy` |
| 焦点描边 | `#339cffb3` | `border_focus` |
| 强调 / 成功 / 警告 / 错误 | `#339cff` / `#40c977` / `#fb6a22` / `#ff6764` | `accent` / `ok` / `warn` / `error` |
| 圆角 | 6px / 8px / 胶囊 | `radius` / `radius_lg` |
| 列表行高 | 30px | `row_height` |

## 设计要点

1. **颜色只有一个出口**：`ui/theme.py` 的 `css()`（QSS 用）与 `qcolor()`（QPainter/QPalette 用）。
   界面代码不许再写颜色字面量 —— 深色底上出现浅色残留，几乎都是某处写死了颜色。
2. **去原生感**：改用 Fusion 样式（原生样式自带的立体感不受调色板控制）；按钮不用渐变/阴影，
   只叠一层白表示 hover/按下；圆角统一 6/8px；页签做成胶囊；列表行高 30、无网格线；
   分割器是 1px 细线；滚动条细条、轨道透明。
3. **字体分工与 Codex 一致**：界面文字用系统 sans，**脚本、报告、输出、diff 用等宽** ——
   这些内容是用来核对的，等宽才看得清列对齐与空格。
4. **语义色跟着主题走**：阻断/错误用 `#ff6764`、通过用 `#40c977`、未跑/非阻断用灰
   （`#afafaf`）。diff 的浅绿/浅粉底在 `#181818` 上会变成刺眼色块，改成低饱和深底 + 亮前景。
5. **栏头**：三栏各一行"小号、次级色、字距略宽"的标题（方案与模板 / 脚本与轮次 / 校验与输出）。
   分区感靠栏头与 1px 细线，不靠边框和凹陷。
6. **主操作**：底栏"开始"用白底黑字（Codex 的主按钮约定），其余按钮是 5% 白叠加 + 1px 边框。

## 必须记住的一个坑（已写成测试）

**Qt 把 8 位 hex 解析成 `#AARRGGBB`，不是 CSS 的 `#RRGGBBAA`。** 于是 Codex 的
`#ffffff0a`（4% 白）在 Qt 里是"不透明的黄"，实测渲染成 `#ffff0a`。这个错误 QSS 不报错、
palette 也不报错，界面就是花的 —— 只有截图取色才看得见（本次就是取色抓出来的）。
所以：半透明颜色一律写成 `(r,g,b,a)` 元组，经 `css()` / `qcolor()` 出口使用。

## 验证方式

`tests/test_theme.py` 两层断言：
- 字符串层：样式表里不许出现 8 位 hex；关键令牌与 Codex 原值一致；
- 像素层：离屏画一遍主窗口，对主背景、只读区、主按钮**取色**（`#181818` / `#0d0d0d` / `#ffffff`）。

两个变异体（把半透明令牌改回 8 位 hex、不装主题）都能让对应用例转红。

## 范围外

- 亮色主题、跟随系统切换：本次不做。
- 布局重构（顶部标题栏、左侧导航、右侧检查器）：本次不动骨架，保持已被测试锁住的三栏结构。
- 图标、动效、字体打包（等宽字体仍是"探测本机可用族"，找不到就退回 monospace）。


## 修订（2026-09-19，用户反馈后）

用户看完第一版提了两点：**"颜色尽量显得高级，尽量圆角"**、**"缩放有问题，不能调节竖向的长度"**。

### 1. 色板精修（不再是 Codex 原值）

照抄的是 Codex 的**结构与比例**（分层关系、字号、行高、三级文字），色值改成有意精修：

| 令牌 | 第一版（= Codex） | 现在 | 为什么 |
| --- | --- | --- | --- |
| `bg` | `#181818` | `#101114` | 冷调更深；"高级感"来自低对比分层，不是把面板刷亮 |
| `bg_elevated` | `#212121` | `#17181c` | 面板只比底色亮一档 |
| `bg_under` | `#0d0d0d` | `#0b0c0e` | 只读底再深一档 |
| `fg` | `#ffffff` | `#ecedf0` | 纯白在高对比深底上偏刺眼/廉价 |
| `accent` | `#339cff` | `#7c9cff` | 偏靛蓝，比"互联网蓝"收敛 |
| `error` | `#ff6764` | `#f2707a` | 语义色降饱和，红色留给真问题 |
| `radius` / `radius_lg` | 6px / 8px | **10px / 14px** | "尽量圆角"；页签改胶囊 |

三栏与底栏各是一张"卡片"（`QWidget#paneCard`：大圆角 + 极淡边框）—— 圆角要看得出来就得有
边框，而栏与栏的分隔感也由它提供（分割条平时透明，只在悬停/拖动时显色）。

### 2. 缩放：两个真实缺陷

- **分割条抓不住**：第一版把 `QSplitter::handle` 的宽/高写成 1px，视觉上像 Codex 的细线，
  但鼠标抓不住。现在用 `setHandleWidth(8)` 在**代码里**设死（不能只靠 QSS：样式表没加载时
  会退回 Qt 默认的 4px，而"能不能用鼠标操作"这种属性不该依赖样式表）。
- **上下两块比例不可调**：三栏区与"历史+设置"区原本是 `QVBoxLayout` 的 1:1，根本不是分割器，
  怎么拖都不可能变。现在改成"上下竖向分割器 + 历史/设置横向分割器"，四个分割器都能拖。
- 另外各栏内部控件的 `minimumSizeHint` 加起来有 400~500px，会**锁死**分割器比例（拖了没反应），
  所以给每块设了可接受的最小高度（140~200px），压小了靠滚动条看。
- **尺寸记忆**：拖完写进设置（`AppSettings.layout`，可读的 JSON 尺寸而非 `saveState()` 字节），
  下次开窗还原。还原必须放在 `showEvent` 里 —— 控件没显示前几何尺寸未定，构造期 `setSizes()`
  会被夹成平均分布（实测：构造期设 `[397,649]`，显示后变 `[238,238]`）。

### 3. 这一轮新增的测试（都做了变异验证）

`tests/test_ui_layout.py`：所有分割器把手 ≥6px、上下能拖（压得下去/顶得上来）、尺寸存得进
设置且还原、坏掉的布局串不致命、把手宽度不依赖样式表；`tests/test_theme.py` 增加"圆角真的画出来了"
（取角落与中心两个像素比较：角落应露出父底色）。


## 修订二（2026-09-19）：缩小窗口时内容被压没

用户反馈："当我缩小窗口的时候，里面的栏目也跟着挤压了，最后会挤压到看不见。"

实测复现（离屏，窗口高 560px）：

| 控件 | 900px 高时 | 560px 高时 |
| --- | --- | --- |
| 方案预览 | 58 | **12** |
| 右栏报告树 | 171 | **35** |
| 右栏输出区 | 171 | **35** |
| 轮次时间线 | 174 | 60 |

根因：这些内部控件**没有最小高度**，QVBoxLayout 会把它们一路压到近零（固定高度的控件，
比如 64px 的补充要求框，反而不受影响 —— 所以越挤越不均匀）。

修法两条：
1. **关键内部控件声明最小高度**：方案预览 90、脚本/diff 视图 140、时间线 80、对话记录 120、
   报告树 110、输出 110、notes 80、历史列表 90、历史详情 60。
2. **栏与窗口声明最小尺寸**：每栏最小宽度 240~300、最小高度 220~260；窗口最小 960×700
   （= 三栏最小宽 + 两条 8px 把手 + 边距）。低于这个尺寸这个界面本来就放不下，与其让 Qt 把内容
   裁掉，不如让窗口管理器直接不许缩到那么小 —— 平铺窗口管理器也会读 min-size 提示。

修完实测：窗口缩到 960×700 时，方案预览 90、报告树 110、输出 110、脚本 299、历史 90，
没有一块被压没。测试里加了三条（窗口最小尺寸、控件最小高度声明、下限尺寸下内容仍可见），
两个变异体（撤掉预览的最小高度、撤掉窗口最小尺寸）都能转红。

**仍然存在的边界**（诚实写明）：平铺窗口管理器如果无视 min-size 提示、强行把窗口压到更小，
Qt 只能**裁切**（内容被切掉一部分）而不是继续压扁。要彻底解决得把每栏内容包进滚动区域，
本轮没做 —— 因为那会改变三栏"填满窗口"的手感，收益不明显。
